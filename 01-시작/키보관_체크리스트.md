# API 키 보관 체크리스트 (실습용)

> [가상 실습 자료] 실습용으로 만든 점검표입니다. 아래 "잘못된 예"의 키 값은 모두 가짜입니다.

## 1. 두 가지 연결을 구분한다
| 구분 | 무엇에 쓰나 | 어떻게 연결하나 | 어디에 남나 |
|---|---|---|---|
| Google 계정 로그인 | Orca 안의 Gemini 에이전트와 채팅 | 브라우저에서 계정 선택 → 허용 | 에이전트 프로그램이 로그인 정보를 따로 보관 |
| Gemini API 키 | 이미지·음성 같은 생성 작업을 스크립트로 돌릴 때 | Google AI Studio에서 발급 | 내가 만든 `.env` 파일 |

## 2. 키 보관 규칙 10가지
1. 키는 `.env` 파일 한 곳에만 둔다. 형식: `GEMINI_API_KEY=발급받은키`
2. `.env`는 `.gitignore`에 넣어 저장 기록(커밋)에 들어가지 않게 한다.
3. 다른 사람에게는 `.env.example`(값 없는 견본)만 나눈다.
4. 키를 채팅 입력창에 붙여 넣지 않는다. 에이전트에게도 보여 주지 않는다.
5. 키를 메신저, 메일, 문서, 스크린샷에 넣지 않는다.
6. 에이전트에게 `.env` 파일을 열거나 내용을 말해 달라고 하지 않는다.
7. 녹화·화면 공유 중에는 키가 보이는 화면을 띄우지 않는다. 보였다면 그 키는 지우고 새로 만든다.
8. 키가 새어 나갔다고 의심되면 AI Studio에서 그 키를 바로 삭제한다.
9. 무료 등급은 하루 요청 수에 한도가 있다. 사용량 화면을 주기적으로 본다.
10. 회사 업무에 쓸 때는 회사의 AI 사용 규정과 결제 계정을 먼저 확인한다.

## 3. 잘못된 예 (따라 하지 말 것)
- 채팅에 "내 키는 AIzaSy-EXAMPLE-ONLY-0000000000 이야, 이걸로 이미지 만들어 줘"라고 쓴다.
- 스크립트 파일 안에 `api_key = "AIzaSy-EXAMPLE-ONLY-0000000000"`처럼 키를 직접 적는다.
- `.env`를 만든 뒤 `.gitignore`를 나중에 추가한다. 그 사이에 커밋하면 키가 기록에 남는다.

## 4. 점검 (녹화 후 체크)
- [ ] `.gitignore`에 `.env` 줄이 있다
- [ ] `git status` 목록에 `.env`가 나오지 않는다
- [ ] `.env.example`에는 키 값이 없다
- [ ] 채팅 기록 어디에도 키가 없다
- [ ] AI Studio 사용량 화면 위치를 안다
