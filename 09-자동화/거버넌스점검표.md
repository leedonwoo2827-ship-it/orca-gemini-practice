# 업무 Assistant 공유·거버넌스 점검표

> 부서에 업무 Assistant를 들이기 전에, 그리고 분기마다 한 번 점검한다. 칸마다 "예 / 아니오 / 해당 없음"과 근거를 적는다.

## 1. 계정과 API 키
| 번호 | 점검 항목 | 결과 | 근거 |
|---|---|---|---|
| A1 | API 키는 `.env` 파일에만 있고 문서·코드·채팅에 없다 | | |
| A2 | `.env`가 `.gitignore`에 들어 있어 공유 저장소에 올라가지 않는다 | | |
| A3 | 키가 드러났을 때 지우고 새로 만드는 담당자와 절차가 있다 | | |
| A4 | 개인 계정이 아니라 업무용 계정으로 쓴다 | | |

## 2. 데이터 등급
| 번호 | 점검 항목 | 결과 | 근거 |
|---|---|---|---|
| B1 | 부서 자료를 공개 / 내부 / 민감 3등급으로 나눈 목록이 있다 | | |
| B2 | 민감 등급 자료는 AI에 넣지 않는다 | | |
| B3 | 개인정보가 들어간 내부 자료는 가명 처리한 뒤에만 넣는다 | | |
| B4 | 쓰는 AI 서비스가 입력 자료를 학습·제품 개선에 쓰는지 약관으로 확인하고 기록했다 (무료 등급과 유료 등급이 다를 수 있다) | | |

## 3. 결과물
| 번호 | 점검 항목 | 결과 | 근거 |
|---|---|---|---|
| C1 | 결과물마다 사람 검토자가 정해져 있다 | | |
| C2 | 숫자·사실이 들어간 결과물은 원본과 대조한 기록을 남긴다 | | |
| C3 | 결과물 보관 위치와 보관 기간이 정해져 있다 | | |
| C4 | 원본은 고치지 않고 결과는 새 파일로 만든다 | | |

## 4. 공유 범위
| 번호 | 점검 항목 | 결과 | 근거 |
|---|---|---|---|
| D1 | 레시피·규칙 파일을 누구와 공유하는지 정했다 (팀 / 부서 / 전사) | | |
| D2 | 저장소 접근 권한이 부서별로 나뉘어 있다 | | |
| D3 | 결과물을 회사 밖으로 보내기 전에 확인하는 사람이 있다 | | |

## 5. 자동화와 비용
| 번호 | 점검 항목 | 결과 | 근거 |
|---|---|---|---|
| E1 | 예약 실행 작업의 목록, 담당자, 실패했을 때 확인 방법이 있다 | | |
| E2 | 무료 한도를 넘을 때의 대응(대기, 유료 전환 기준, 비용 승인자)이 정해져 있다 | | |
