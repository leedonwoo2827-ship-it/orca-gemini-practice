# [가상 실습 자료] 새솔상사 제안 준비 회의 메모 (대응 방안 아이디어)

- 일시: 2027년 1월 13일(수) 14:00 / 참석: 박서연, 김하늘, 이준호, 최민지, 오세훈
- 메모: 김하늘. 말한 순서대로 적었다. 요구사항 ID는 아직 안 붙였다.

1. 도구는 Orca와 Gemini 에이전트 조합으로 간다. 무료 계정으로 시작하고, 한도가 모자라면 AI Pro 구독을 부서당 1개만 쓴다. 구독비는 가격 제안서에 따로 적는다. (박서연)
2. 회의록·할 일 목록은 녹취 메모를 양식 파일대로 정리하는 방식. 녹음 파일은 API로 받아쓰기. (김하늘)
3. 보고서·공문·메일 초안은 새솔상사 양식 파일을 받아 저장소에 넣고 양식대로 쓰게 한다. (김하늘)
4. 엑셀은 중복·오류 점검표부터 만들고 집계·차트로 간다. 검산 단계를 꼭 넣는다. (최민지)
5. 규정 검색은 규정 폴더를 저장소로 만들고 답마다 조항 번호를 달게 한다. 근거 검증 단계도 넣는다. (최민지)
6. 스캔 문서·캡처는 이미지 읽기 → 표 → 원본 대조 순서. (이준호)
7. 교육용 이미지는 API 키로 스크립트 생성. 영상은 요약과 시간 목차. (이준호)
8. 반복 요청은 레시피 폴더로 만들고, 주간 보고는 예약 실행. (김하늘)
9. 교육은 기본 4시간 + 심화 4시간. 기본은 부서별로 나눠서 3회 할 수도 있다. 교육 자료는 우리 강의 영상을 줄여서 쓰자. (최민지)
10. 사용 매뉴얼은 기능별 1쪽짜리, 요청문 예시집은 기능마다 3개씩. (이준호)
11. 이용 지원 창구는 메신저 채널 하나 + 주 1회 원격 상담 시간. (오세훈)
12. 데이터 등급은 공개 / 내부 / 민감 3등급. 민감 등급은 AI 입력 금지, 내부 등급은 가명 처리 후 입력. (박서연)
13. 개인정보는 우리 교육 과정의 가명 처리 절차(이름·연락처 가리기 → 점검표 확인)를 그대로 쓴다. (김하늘)
14. 결과물은 부서별 저장소에 두고 1년 보관 후 정리. (박서연)
15. API 키는 .env에만 두고 저장소 공유에서 빼는 설정(.gitignore)을 기본으로 한다. (오세훈)
16. 부서별 저장소를 나누면 접근 권한도 자연스럽게 나뉜다. (오세훈)
17. 보안 점검은 이용 지원 시작 2주 전에 받도록 일정에 넣는다. (박서연)
18. 착수 보고는 계약 후 10일 안에. 산출물 목록과 제출 일정은 착수 보고서 부록으로. (박서연)
19. 효과 지표는 회의록 작성 시간, 주간 보고 작성 시간, 월 이용자 수. 진단 때 한 번, 종료 때 한 번 잰다. (최민지)
20. 시범 부서 의견은 진단 단계 인터뷰 + 교육 후 설문으로 두 번 듣는다. (최민지)
21. 점심은 다음 회의 때 같이 먹자. (오세훈)
