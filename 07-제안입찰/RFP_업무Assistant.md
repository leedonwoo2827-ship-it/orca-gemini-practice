# [가상 실습 자료] 제안요청서

> 이 문서는 강의 실습용으로 지어낸 **가상의 제안요청서**입니다. 새솔상사, 사업, 숫자는 모두 지어낸 것이며 실제 회사·공고와 관계가 없습니다. 분석 연습을 위해 모호한 표현과 서로 맞지 않는 숫자를 일부러 넣었습니다.

**사업명**: 생성형 AI 기반 업무 Assistant 구축 및 이용
**발주사**: 새솔상사(가상) 경영지원본부
**공고 번호**: 새솔-2027-003 (가상)

## 1. 사업 개요

### 1.1 추진 배경
새솔상사는 사무용품 유통 회사다. 임직원이 회의록, 보고서, 엑셀 집계, 규정 찾기 같은 반복 업무에 많은 시간을 쓴다. 일부 직원은 개인 계정으로 외부 AI 서비스를 쓰고 있어, 회사 자료가 밖으로 나갈 위험도 있다. 이에 회사가 관리하는 생성형 AI 업무 Assistant를 도입하고, 안전하게 쓰는 규칙과 교육을 함께 마련하려 한다.

### 1.2 사업 목표
1. 반복 문서·데이터 업무의 처리 시간을 줄인다.
2. 데이터 등급과 보안 규칙을 지키며 AI를 쓰는 체계를 만든다.
3. 임직원이 스스로 Assistant를 활용하도록 교육한다.

### 1.3 사업 범위 요약
| 항목 | 내용 |
|---|---|
| 사업 기간 | 계약일로부터 **6개월** |
| 이용 대상 | 시범 부서 3곳(경영지원팀, 영업관리팀, 교육팀) 임직원 **120명** |
| 사업 예산 | 96,000,000원 (부가세 포함, 가상) |

## 3. 세부 요구사항

### 3.1 기능 요구사항 (SFR)
| ID | 요구사항 |
|---|---|
| SFR-001 | 회의 메모와 녹음 파일로 회의록과 할 일 목록을 만든다. |
| SFR-002 | 보고서·공문·메일 초안을 사내 양식에 맞춰 만든다. |
| SFR-003 | 엑셀·CSV 자료의 중복과 오류를 찾고 집계표와 차트를 만든다. |
| SFR-004 | 사내 규정 문서를 근거로 질문에 답하고, 답마다 근거 조항을 표시한다. |
| SFR-005 | 문서를 영어·중국어로 번역하고, 용어집에 맞춰 표기를 통일한다. |
| SFR-006 | 스캔 문서와 캡처 이미지 속 글자와 표를 편집 가능한 파일로 바꾼다. |
| SFR-007 | 교육·홍보용 이미지를 만들고, 영상의 요약과 시간 목차를 만든다. |
| SFR-008 | 반복 요청을 재사용할 수 있게 저장하고, 정해진 시간에 자동으로 실행한다. |

### 3.2 서비스 요구사항 (SER)
| ID | 요구사항 |
|---|---|
| SER-001 | 사용자 교육을 기본·심화 2회 이상 실시한다. 회당 4시간, 대상은 임직원 **150명**이다. |
| SER-002 | 이용 지원 창구를 운영하고 문의에 **신속히** 답한다. |
| SER-003 | 기능별 사용 매뉴얼과 요청문 예시집을 제공한다. |
| SER-004 | 이용 지원 기간 동안 매월 이용 현황 보고서를 낸다. |

### 3.3 데이터 요구사항 (DAR)
| ID | 요구사항 |
|---|---|
| DAR-001 | 업무 자료를 3등급 이상으로 나누는 데이터 등급 기준을 만들고, 등급별로 AI 입력 가능 여부를 정한다. |
| DAR-002 | 개인정보가 들어간 자료는 가명 처리한 뒤에만 AI에 입력한다. |
| DAR-003 | AI가 만든 결과물의 보관 위치와 보관 기간을 정한다. |

### 3.4 보안 요구사항 (SEC)
| ID | 요구사항 |
|---|---|
| SEC-001 | API 키 같은 인증 정보는 별도 파일에 보관하고, 문서·코드·화면에 드러나지 않게 한다. |
| SEC-002 | 외부 AI 서비스를 쓸 때 입력 자료가 모델 학습에 쓰이는지 확인하고 그 결과를 문서로 남긴다. |
| SEC-003 | 부서별로 접근할 수 있는 자료와 결과물을 나눈다. |
| SEC-004 | 이용 지원 시작 전에 발주사의 보안 점검을 1회 이상 받는다. |

### 3.5 사업 관리 요구사항 (PMR)
| ID | 요구사항 |
|---|---|
| PMR-001 | 계약 후 14일 안에 착수 보고를 하고, 중간·완료 보고를 한다. |
| PMR-002 | 사업 책임자는 유사 사업 경력이 있어야 하며, **필요 시** 발주사에 상주한다. |
| PMR-003 | 산출물 목록과 제출 일정을 착수 보고서에 넣는다. |

### 3.6 제안서 작성 지침
- 제안서 본문은 50쪽 이내로 쓰고, 아래 평가 항목 순서대로 장을 나눈다.
- 도입 후 효과를 **측정할 수 있는 지표**(예: 처리 시간, 이용률)와 측정 방법을 제시한다.
- 무료 또는 저비용 도구를 우선 검토하고, 유료 구독이 필요하면 비용을 따로 밝힌다.
- 시범 부서의 의견을 듣는 절차를 사업 중에 두 번 이상 둔다.
- 기존 사내 메신저와 연계하는 방안은 **가능하면** 제시한다.
